# 测试策略

> **状态**：单元测试与集成测试已落地（78 个用例）。
> 端到端测试**尚未存在**（链路未实现）。评测方案见 [`evaluation-plan.md`](evaluation-plan.md)。

---

## 1. 为什么要分层

不同层次的测试回答不同的问题，混在一起会产生两种浪费：**用集成测试验证纯逻辑**（慢且脆弱），或**用单元测试验证集成行为**（假通过）。

| 层 | 回答的问题 | 依赖 | 速度 |
| --- | --- | --- | --- |
| 单元 | 这个函数/模型的逻辑对吗？ | 无 | 毫秒 |
| 集成 | 各组件拼起来能正确工作吗？ | 应用 + 数据库 + Mock 工具 | 秒 |
| 端到端 | 用户能得到想要的结果吗？ | 全栈 | 十秒～分钟 |
| 评测 | Agent 回答的**质量**如何？ | 全栈 + 数据集 | 分钟～小时 |

**边界原则**：
- 能用单元测试验证的，绝不放到集成层。
- 需要真实数据库才能验证的，绝不放在单元层用 mock 假装。
- **评测不是测试的替代品。** 测试断言"对/错"，评测度量"多好"。

## 2. 单元测试（`tests/unit/`）

**范围**：纯逻辑、模型校验、格式化、配置解析。**不启动应用，不访问网络，不使用数据库。**

| 文件 | 覆盖内容 |
| --- | --- |
| `test_domain_trip.py` | 需求模型的全部校验规则、空值语义、槽位缺失检查 |
| `test_config.py` | 配置加载、前缀隔离、启动期校验、密钥不外泄 |
| `test_logging.py` | trace id 传播、JSON / console 格式化、日志记录形状 |

**约定**：
- 测试名描述**行为**而非实现：`test_day_count_contradicting_the_range_is_rejected` 而不是 `test_validator_2`。
- 用 `class TestXxx` 按规则分组（`TestDateRules`、`TestBudget`），让失败信息自带上下文。
- 每个断言都应当能回答"这条业务规则是什么"。
- **禁止**：为通过测试而放宽类型、删除断言、大范围 `# type: ignore`。

当前实测：`tests/unit/` 52 个用例。

---

## 3. 集成测试（`tests/integration/`）

**范围**：应用装配、HTTP 契约、中间件、异常映射、数据库交互、工具适配器。

| 文件 | 覆盖内容 |
| --- | --- |
| `test_health_endpoints.py` | 探针状态码与响应形状、trace 传播、错误信封、OpenAPI |
| `test_app_lifecycle.py` | 应用工厂、启动校验、lifespan 启停、无隐式数据库连接 |

**关键约定：HTTP 测试走真实的 ASGI 应用，不在传输层打桩。**

```python
transport = ASGITransport(app=app, raise_app_exceptions=False)
```

这样路由、中间件、异常处理器、序列化全部被真实执行。**在传输层打桩会让这些全部失去覆盖**——而它们恰恰是最容易出错的部分。

**失败路径必须被显式覆盖。** 应用刻意不提供任何会失败的端点，测试通过 `app.add_api_route` 临时挂载探针路由来触发 500 / 422，而不是削弱生产代码：

```python
def explode() -> None:
    raise RuntimeError("database password hunter2 leaked")
```

然后断言**内部信息没有泄漏**（`"hunter2" not in response.text`），同时 trace id **确实**返回了。

**未来加入数据库后**：集成测试使用 Compose 提供的 PostgreSQL（或 testcontainers），每个测试用例在事务中运行并回滚。**不允许用 SQLite 替代**——方言差异会让集成测试失去意义。

**未来加入工具后**：使用 Mock 工具实现，并对 Mock 与真实实现跑同一套契约测试（见 [`../contracts/tool-contracts.md`](../contracts/tool-contracts.md) 第 9 节）。

当前实测：`tests/integration/` 26 个用例。

## 4. 端到端测试（`tests/e2e/`）

**范围**：一次完整用户旅程——自然语言进，结构化行程出。

**当前状态：不存在。** 端到端链路（HTTP → Agent 工作流 → 工具 → 持久化）尚未实现，现在写只能断言 stub，无法证明任何事。目录中只有 README 说明此事。

**标记为 `e2e`**，默认包含在全量运行中，可用 `make test-e2e` 单独执行。CI 目前执行全量 `pytest`（当前无 e2e 用例，因此无额外开销）；等 e2e 用例引入外部依赖后，改为主流水线跑 `-m "not e2e"`、独立流水线跑 e2e。

**首个 e2e 测试应当断言**：
1. 提交"周五晚深圳出发，长沙三天，预算 2000，爱美食和人文，不想太满"。
2. 系统识别出缺失槽位并追问（而非直接生成）。
3. 补充信息后返回行程。
4. 行程满足：天数 = 3、预算 ≤ 2000、节奏为 relaxed、含美食与人文类条目。
5. 每个条目都带 `source` 与 `fetchedAt`。
6. **未提及的部分在增量修改后逐字节不变。**

## 5. 测试替身的使用规则

| 替身 | 允许用于 | 禁止用于 |
| --- | --- | --- |
| Mock 工具实现 | 集成 / 端到端 / 评测 | 替代单元测试中的纯函数 |
| `ASGITransport` | 集成 | 需要真实网络的场景 |
| DB 事务回滚 | 集成 | — |
| `monkeypatch` | 环境变量、时间 | 打桩被测模块自身的核心逻辑 |
| 打桩数据库驱动 | ❌ 一律禁止 | 用 SQLite 或假驱动替代 PostgreSQL |

**原则**：替身只能替换**我们无法控制的边界**（外部网络、时间），不能替换我们要验证的逻辑。

## 6. 测试数据的构造

使用 `tests/conftest.py` 中的工厂函数 + 显式 fixture，**不使用共享的可变模块级状态**。

```python
def make_settings(**overrides: Any) -> Settings:
    return Settings(_env_file=None, **overrides)
```

`_env_file=None` 是必须的：否则开发机的 `.env` 会静默改变测试结果。这类"在我机器上能过"的问题必须在构造层面消除，而不是靠约定。

**禁止**：让测试之间通过模块级变量或文件系统隐式传递状态。

## 7. 需要显式覆盖的场景

这些是最容易在真实使用中造成伤害、因而必须被测试锁住的行为：

- [x] 入站 `X-Trace-Id` 被复用；超长值被替换
- [x] 未处理异常返回 500 且**不泄漏**内部信息，同时**保留** trace id
- [x] 校验失败**不回显**用户原始输入
- [x] `/ready` 在数据库未接入时报告 `not_configured` 而非 `ok`
- [x] 配置自相矛盾时启动失败，并指出**环境变量名**
- [x] API 密钥不出现在 `repr()` / `str()` 中
- [x] `None` 语义：`travelers=None` 不被当作 1 人
- [x] 未知字段被拒绝而非静默丢弃
- [ ] 工具超时被归类为可重试；参数错误被归类为不可重试
- [ ] 重试次数不超过上限（用调用计数器断言）
- [ ] 缓存命中时 `fetched_at` 保持原始值
- [ ] 过期数据触发重新查询；失败时标记 `is_stale` 并告警
- [ ] 增量修改后未提及的天数逐字节不变
- [ ] 并发修改同一行程时版本校验拒绝后写

## 8. 覆盖率

**覆盖率是信号，不是目标。** 不设 `--cov-fail-under` 阈值：在没有基线的情况下挑一个数字，只会催生为凑数字而写的测试。

当前实测 **98%**（431 条语句，8 条未覆盖）。未覆盖的主要是防御性分支（如 `Runtime` 未初始化时的 `RuntimeError`、`AppError` 的兜底处理器）。

**审查时应关注**：新增的业务规则是否有对应测试，而不是覆盖率数字涨了没有。

## 9. CI 职责

`.github/workflows/ci.yml` 在两个作业中执行：

| 作业 | 步骤 | 等价本地命令 |
| --- | --- | --- |
| `quality` | `ruff check` → `ruff format --check` → `mypy` | `make check` |
| `test` | `pytest --cov`（Python 3.12 与 3.13 矩阵） | `make cov` |

**本地命令与 CI 完全一致**——同一个 Makefile 目标，避免"本地通过、CI 失败"。

CI 与本地都使用 `uv sync --all-groups` 从 `uv.lock` 安装，并在 CI 中设置 `UV_FROZEN=1`，确保锁文件过期时**构建失败而不是静默重新解析**。

**尚未加入 CI 的检查**（需要先有对应实现）：
- 端到端测试（需 Compose 服务）
- 数据库迁移检查（`alembic check`，需先有 `migrations/`）
- 依赖漏洞扫描
- 分层依赖方向的机械校验（例如用 import-linter 断言 `domain/` 不依赖 FastAPI）——**这项建议尽早补上**，因为它是 ADR-0001 唯一没有被自动化的约束
